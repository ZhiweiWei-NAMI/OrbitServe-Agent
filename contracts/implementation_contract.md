# OrbitServe V0 module contract (A00, 2026-10-16)

Only this standalone project is modified. External raw data: /workspace/shared/orbitserve-data. External run artifacts: /workspace/shared/orbitserve-runs. No raw imagery or generated binary products committed.

Python package `src/orbitserve`, JSON-compatible dictionaries as public values.

## Data A01
`data.py`: `acquire(data_root: Path, cases=None) -> dict` and CLI scripts/prepare_data.py. Dataset root `earthbench/question2`, `earthbench/question4`, `cases/<case_id>/{task.json,assets.json,imagery/before/*.tif,imagery/after/*.tif}`. References in separate external `evaluation/`, never copied to workers. Three 250x250 approximately 5km x 5km projected 20m AOIs. All six dates have B02 B03 B04 B08 B11 SCL. Assets list JSON `assets` each with `path` relative to case, `phase`, `band`, `scale`, `offset`, `nodata`, `sha256`, original source/item/CRS/grid metadata. task.json has case_id, width,height,crs,transform (first six Affine coefficients), threshold=0.0, method=MNDWI, source_node=A, pixel_size_m=20. Metadata must represent actual inputs, never fabricated values. If output differs coordinate with science immediately.

## Science A02
`science.py`: `run_operator(tool_id: str, case_dir: str|Path, output_dir: str|Path, params: dict) -> dict` returning JSON result including `files` list relative output paths, statistics and actual formulas. tools `earthbench_ndvi`, `earthbench_tvdi`, `water_tile`, `water_merge`, `water_full`. `water_tile` params.window=[row_off,col_off,height,width], fixed threshold; outputs window rasters and JSON. `water_merge` params.tile_dirs list of node-local received tile product directories, reconstruct exact full grid, export change.tif (0=unknown,1=stable_nonwater,2=stable_water,3=gained,4=lost), before_water.tif,after_water.tif,valid_common.tif,stats.json,changes.geojson,map.png. full calls tile then merge. Scaling asset-specific, SCL nearest, continuous bilinear, common-valid masking. Both tile/full same algorithm. `water_merge` must not reread original imagery, only task/assets and tile outputs. Science never reads evaluation. E0 baseline through common harness provided by A00.

## Forecast/planning A04
`forecast.py`: `forecast(observation_history:list[dict],known_contact_plan:list[dict],horizon_s:float,candidate_workload=None,source_kind='analytical_reference')->dict` with all spec fields. Learned mode explicit error. observed state has timestamp, nodes list (node_id,capabilities,compute_pixels_s,memory_bytes,storage_bytes,energy_j,queue_work_pixels,available_after_s), assets metadata. Reference uses observed queues + contact plan analytically, no hidden scenarios.
`planning.py`: `plan(task:dict,asset_catalog:dict,skill_catalog:dict,forecast_graph:dict)->dict`; plan fields plan_id,version=1,mission_id,case_id,forecast_id,grain,tile_size,steps,delivery. each step `step_id`, `tool_id`, `dependencies` (step_ids), `params`, `required_capability`, `estimated_memory_bytes`, `estimated_compute_pixels`, `allowed_nodes` (>=2 for analysis), input_refs. Steps water_tile per actual window then water_merge (depends all tile steps). No assigned_node. All steps initially owned at source A for discovery/submission; this is submission ownership, not execution assignment. Plan bounded to original AOI. fixture helper for E2 returns identical observed_snapshot, only differing future node/edge fields; explicit test_fixture.
`policy.py`: `choose_action(local_observation:dict, task:dict, received_neighbors:list[dict], forecast_view:dict)->dict`, returns local/request/wait with destination, candidate cost details. Inputs local fields node_id,capabilities,compute_pixels_s,memory_bytes,storage_bytes,energy_j,queue_work_pixels,busy_until_s,now; ads additionally timestamp. Costs wait+bytes/throughput+queue+compute+return. Missing capability and resource limits reject. Called inside each actual worker. Target admission runtime checks own current state; sender never injects queue directly.

## Runtime A03/A05
`runtime.py`: `run_distributed(plan:dict,case_dir:Path,run_dir:Path,scenario:str='normal',config:dict|None=None)->dict`; starts four actual processes A,B,C,G, source preload only A. It returns status=delivered only ground fully validated outputs, `outputs_dir`, process and transfer evidence. Scenarios normal,busy_b,ground_outage,transfer_outage. Fixed input plan object reusable for E3. Source-owned DAG progresses from received result receipts. Each process local policy instance + own admission; neighbor ads, requests, receipts, plans ALL through link broker, broker only routes not decides. Real file bytes carried through broker queues/socket; temporary writes unavailable until SHA256 verified; bandwidth capacity shared per directed edge and monotonic wall-clock. Transfers record offsets/pause/resume and byte hashing. Workers restricted from other roots/reference/network, preferably Landlock or bwrap; fail closed or honestly BLOCKED if enforcement unavailable. Read-only source/dependencies and own node root only. Hidden scenario script owned broker, not forecast/policies. Runtime known contact plan is separate from unannounced failure/queue events. G submits plan then receives delivery; no hidden post-outage control. Four nodes node roles/capabilities/resources config separate, no hardcoded B choice. Runtime tool calls include job_id/run/mission/plan/step, accepted/queued/running/succeeded/failed, actual PID/node/input and output artifact hashes. No remote raw path passed into workers.

Shared evidence JSONL names forecasts,plans,decisions,tool_calls,transfers,node_events,control_messages,observations. Every event timestamp monotonic relative run start, run_id, relevant mission/plan/step/job/artifact fields. A00 collects baseline, manifests, experiment acceptance; independent A06 derives verdicts from actual outputs/logs and clean rerun. Native authors use disjoint files, not git operations; A00 only commits at integration.
